Share sessions with teammates and move work forward together. See what others
are working on and pick up where they left off.

Coconet organizes your team's Agent sessions into a work graph. Follow project
progress, find relevant work, and fork a teammate's conversation to continue it.

Supports **Codex, Claude Code and Cursor CLI** on macOS and Linux.

## Get started

Install with one command:

```sh
npm install -g coconet
```

Then run this in the work directory you want to connect:

```sh
coconet connect
```

Sign in on the page that opens (on Linux, open the link from your terminal), then
join or create a project to set up a shared online workspace.

Send the project ID or link to your teammates. They can connect their own work
directories to the same project:

```sh
coconet connect coco_PROJECT_ID
```

Replace `coco_PROJECT_ID` with the complete project ID. The default Dashboard is
at <https://coconet.space/>.

New conversation updates sync after connecting; existing history is not imported
in full automatically. To view progress on the web without connecting an Agent,
just open the project link. No installation is needed.

## Working together

Work with your Agent as usual, and progress syncs automatically. When you want to
collaborate, you can ask:

- “See what my teammates are working on.”
- “What did we decide about login, and who worked on it?”
- “Find my teammate's session and pull it down so we can finish the remaining work.”

Your Agent can use Coconet tools to explore the work graph, search and read
conversations, and continue a session. Continuing a session does not restore the
code to that point in time. Check your current code state and use `git` to keep
code in sync.

## Where data and inference live

Work graphs are generated by Agents on member devices, using their existing
login, provider and default model. There are no extra model keys or call limits
to configure. Background inference uses the executing Agent account's quota.

The server manages accounts and projects, coordinates synchronization, stores
work graph checkpoints, and relays content temporarily. Clients save local
replicas of the project's retained sessions in the background. Conversation
search runs locally.

A project ID lets signed-in users join the project. Share project IDs and links
only with your intended collaborators.

See [data sharing and retention](docs/data-sharing.md) and
[architecture and data flow](docs/architecture.md) for details.

## Use your own server

Coconet supports running a standalone server on Linux for private deployments
and collaboration over a local network.

To connect to a self-hosted server, include its address:

```sh
coconet connect --server 'https://coconet.example.com'
coconet connect coco_PROJECT_ID --server 'https://coconet.example.com'
```

See the [self-hosting guide](docs/self-hosting.md) for deployment, authentication,
HTTPS and storage configuration.

## Build from source

Requires Go 1.26.9+, Node.js 24.22+, npm, Python 3 and Git.

```sh
go build -o bin/coconet-server ./apps/server
make check
```

See [development](docs/development.md) for client builds, browser tests and
packaging.
